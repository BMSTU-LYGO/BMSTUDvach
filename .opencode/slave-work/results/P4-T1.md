1) Клавиатура — `src/views/PlatinumView.vue`
- Строки остались `RouterLink` (нативная семантика ссылки + `href` → достижимы с клавиатуры, `Enter` в браузере даёт переход), поверх добавлен `@keydown` на строке: `ArrowDown`/`ArrowUp` двигают выделение на соседнюю строку, `Home`/`End` — к краям списка, `Enter` открывает историю. `preventDefault()` на Enter гасит дефолтную активацию ссылки — двойной навигации нет.
- Порядок важен: сначала `focusStory(id)` + `emitSceneEvent({ type: 'archive-focus', target: id })`, потом перенос DOM-фокуса. Благодаря этому `blur` покидаемой строки не успевает отпустить фокус, который уже взяла новая строка (иначе в сцену улетало бы лишнее `archive-focus: null`).
- `focusRow()` (наведение мышью) не объявляет ничего; объявляет только `announceFragment()` — из обработчика `@focus` строки и из клавиатурного перемещения. Дедупликация по последнему объявленному id: A → B → A снова говорит, повтор того же фрагмента — нет.
- Область объявления — `<p class="archive-live" aria-live="polite" data-testid="archive-live">`, визуально скрыта (1px + `clip-path`), присутствует в DOM всегда, чтобы скринридер увидел изменение текста, а не появление узла.

2) Переключатель регистра «3D / только текст»
- Кнопка в шапке рядом со счётчиком фрагментов: `aria-pressed` + стабильное доступное имя «3D-пространство архива» (видимое слово «3D» входит в имя — WCAG 2.5.3), индикатор «вкл/выкл» помечен `aria-hidden`, чтобы не дублировать состояние.
- Состояние: `localStorage['bmstudvach-archive-3d'] = 'on' | 'off'`, по умолчанию 3D включён; при старте вью читает хранилище, при ошибке доступа (private mode) — тихий откат на 3D.
- Вью и канвас живут в разных деревьях компонентов, поэтому выбор передаётся window-событием `bmstudvach:archive-3d` (`detail: { enabled }`) — тем же приёмом, что уже используется в проекте (`bmstudvach:open-scan` в `useNavShortcuts`). Имена ключа и события продублированы в двух файлах со взаимными ссылками в комментариях (общий модуль не заводился — файл за границами задачи).

3) Канвас — `src/components/three/ArchiveSpaceCanvas.vue`
- Сессия WebGL вынесена в однострочный дочерний компонент `ArchiveScene` (`defineComponent` внутри SFC), который держит `useThreeScene`. При переходе в текстовый режим дочерний компонент размонтируется → `useThreeScene` отдаёт контекст (`renderer.dispose()`, `releaseSlot()`), `MAX_ACTIVE_CONTEXTS` не трогаем; при возврате в 3D канвас создаётся заново (свежий элемент → свежий контекст). Сам `<canvas>` остался в шаблоне обёртки (иначе scoped-стили и `pointer-events` переехали бы внутрь render-функции без scope-id).
- В текстовом режиме канвас не рендерится вообще (`v-if`), обёртка получает `aria-hidden="true"` и `display: none`; DOM-слой вью полностью функционален.
- A11y: канвас остался `aria-hidden="true"` (декоративный слой), обёртка получила `role="img"` + `aria-label="Архивное пространство: кольца эпох и фрагменты историй"` — у слоя появилась понятная подпись для скринридера.
- Правило «камера летит только при открытии» сохранено: клавиатурное перемещение шлёт `archive-focus` (только `archive.focus`, без `travelToFocus`), а `Enter` шлёт `archive-open` — как и клик по фрагменту в 3D.
- `prefersReducedMotion()` по-прежнему уходит в `archive.update({ reducedMotion })`; новых «прыжков» не добавлено, новые CSS-переходы сняты в `@media (prefers-reduced-motion: reduce)`.
