SUMMARY:
Each board cluster now derives its whole look from the same `seed = hash(slug)`, computed once per
board in `setBoards` and shared by the layout, silhouette, accent and spin. The shape is picked from
`GEOMETRY_VARIANTS = ['icosahedron', 'octahedron', 'dodecahedron', 'tetrahedron', 'box']` and built
by a new `variantGeometry()` helper used for both the glow-shaded node mesh and its `EdgesGeometry`
wireframe (box gets `BOX_SCALE = 1.45` so it reads the same size as the polyhedra). The accent color
comes from `NODE_PALETTE = [AMBER, STEEL, STEEL_LIGHT, DEEP, GLOW]` and is stored on `BoardNode.color`
so `update` can restore it every frame — hover/shared states still override it with `AMBER_BRIGHT`.
Spin is `MIN_SPIN + (seed % 100) * 0.005` (0.1–0.6 rad/s) stored as `BoardNode.rotationSpeed`, applied
in `update` as `rotation.y += dt * speed` plus a slower `rotation.x` for variety. `BoardNode` gained
`variant`, `color` and `rotationSpeed`; `pulseAt`, `sendReply`, `launchPulse`, `launchEnvoyPacket`,
travel/morph logic, Fibonacci-lattice positioning and `threadCount → scale` are untouched.

BLOCKERS/FOLLOWUPS:
- No blockers.
- Rotation is now driven by `BoardNode.rotationSpeed`, but `prefers-reduced-motion` still spins the
  nodes — P6-T3 ("отключить вращение узлов") should gate `group.rotation` on that flag.
- `DEEP` (0x1a1e2e) is close to the fog color, so one palette slot renders quite dim; if that reads
  badly in the browser, a follow-up can remap or brighten that slot without touching the palette size.
- `update()` still writes `n.mat.uniforms.uColor`/`n.edgeMat.color` every frame via `setHex`; a later
  phase could skip the per-frame color write for non-highlighted nodes to save a little CPU.
- Geometry is chosen per board but the wireframe and the solid use the same variant — if nodes look
  too uniform, a follow-up could give the wireframe its own second variant.
