ЧТО СДЕЛАТЬ:
1. frontend/src/composables/useTransmit.ts:
   - const tx = useTransmit() → { submitting: Readonly<Ref<boolean>>, error: Ref<TransmitError|null>, successToken: Ref<number>, lastInput: Ref<unknown>, run(input, apiCall), retry(), reset() }
   - run(input, fn): ставит submitting, чистит error; ждёт fn(); успех → successToken++, error=null, reset submitting. Ошибка → error = classifyError(err), submitting=false. lastInput хранит input для retry.
   - retry(): повтор run с lastInput (нужен сохранённый fn — держи замыкание последней попытки).
   - offline-авто-retry: если error.kind==='offline', слушать window 'online' → один автоматический retry(); слушатели чистятся (onScopeDispose/onUnmounted; composable вызывается из setup, используй getCurrentInstance-safe подход или экспорт destroy()).
   - throttle: если kind==='throttle' и retryAfterSec>0 — по достечении 0 авто-retry НЕ делаем (уважать лимит, показать «повторить»); это решит Notice кнопкой.
   - НИЧЕГО не логирует в console кроме warn на неизвестных ошибках — молча в error state.
2. frontend/src/components/composer/TransmitNotice.vue:
   - props: error: TransmitError | null; кнопка retry показывается для kinds: offline(server retry тоже), server, unknown, throttle (после истечения countdown), НЕ для locked/notFound (нет смысла).
   - countdown для throttle: «повтор через Nс», живой тик (setInterval 1s, cleanup), по достижении 0 — кнопка «повторить».
   - validation: если fields непусто — список «поле: сообщение» (первые 3), ru-метки полей: title→заголовок, body→сообщение, comment→комментарий, reason→причина, attachments→файлы, non_field_errors→нет special.
   - a11y: role=alert, aria-live="polite"; style = paper/ink (см. --danger из ReportProbe/SignalDock error-линий), компактный, не баннер; NetworkIcon ('close'/'error' глиф на выбор — существующие имена смотри в NetworkIcon.vue).
   - emits: retry.
