1. Создать frontend/src/api/errors.ts:
   - export type TransmitErrorKind = 'offline' | 'throttle' | 'validation' | 'tooLarge' | 'locked' | 'notFound' | 'server' | 'unknown'
   - export interface TransmitError { kind; messageRu: string; detail?: string; retryAfterSec?: number; fields?: Record<string, string[]> }
   - export function classifyError(err: unknown): TransmitError
     * TypeError/«Failed to fetch»/AbortError + !navigator.onLine → offline, messageRu «Сеть недоступна. Черновик сохранён — попробуем, когда связь вернётся.»
     * 429 → throttle: извлечь N секунд из DRF detail (EN «Expected available in N seconds.» и возможный RU вариант), иначе fallback-оценка. messageRu «Слишком много сигналов. Повтор через N с.» (без секундной точности — N из retryAfterSec)
     * 400 → validation: поля из err.errors (filter пустых), messageRu — первые 2 сообщения через « · » (как apiErrorMessage сейчас); fields = err.errors
     * 413 → tooLarge «Файл или сообщение больше, чем выдерживает сеть.»
     * 403/409, если бэкенд отдаёт за закрытый/заблокированный тред (ПРОВЕРЬ backend, ищи lock/locked в models/api; если есть отдельный detail — матчи по нему) → locked «Тред закрыт для новых сигналов.»
     * 404 → notFound «Пост или тред больше не здесь.»
     * 5xx → server «Сервер сети не отвечает. Попробуй ещё раз.»
     * всё остальное → unknown с русским fallback.
   - НИКОГДА не показывать пользователю англ. «Failed to fetch»/«Request failed» как messageRu.
